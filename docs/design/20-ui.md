### 共通の作り方

- **画面の部品は、押された操作を戻り値で返します**（`MenuAction`・`PauseAction`・`ResultAction`・`DebugPanelResult`）。プレイを始める・メニューに戻るなどの実際の処理は `App` が行います。部品は `App` を知りません。
  - 例外: `MainMenu::draw` の `cameraMode` と、練習場のプリセットの選択（`GameData::selectSandboxPreset`）は、部品が直接書き換えます。
- 画面の部品は、毎フレーム呼ばれて描き直されます（Dear ImGui の即時モード）。選んだ内容など、フレームをまたいで覚えるものは、クラスのメンバ（`MainMenu::config_`・`StatsDashboard` の絞り込み）に持ちます。
- ウィンドウの大きさ・位置は毎フレーム `ImGuiCond_Always` で決め、`imgui.ini` に保存しません（`App::initWindow` で `IniFilename = nullptr`）。デバッグパネルだけは、最初の位置を決めた後は動かせます。
- ピクセル単位の大きさには `ui::px()` で倍率を掛けます（4.1）。

## 2. 各画面

### 2.1 `MainMenu`（クラス）

**役割**: メインメニュー。キャラ・モード・ステージ・各モードの設定・クールダウン・視界・カメラ・解像度を選び、「開始」で `MatchConfig` を返します。「記録を見る」「統計を見る」で、メニューの代わりに記録・統計の画面を出します。

**背景**（根拠: 各手順のコミット）: 手順ごとに項目が足されてきました（手順 2 でスキルドッジの設定、手順 3 でステージ、手順 4 でスキルショットの設定、手順 5 で記録、手順 6 で統計）。

| 関数 | 説明 |
|---|---|
| `MenuAction draw(GameData& data, CameraMode& cameraMode, const ResultStore& results, const DisplayState& display)` | メニューを描く。記録・統計の画面を開いている時は、そちらだけを描く。`cameraMode` はプレイ中に Y キーでも変わるので、メニューでは持たずに `App` の値を直接変える。`data` は練習場のプリセットを選んだ時に書き換える。`display` は「画面」の欄（解像度）に使う。解像度はウィンドウの大きさを変える必要があるので、選んだ値を `MenuAction` で返し、`App` が大きさを変えて保存する |
| `void setConfig(const MatchConfig& config)` | 前回のプレイの設定を、次にメニューを開いた時の初期値にする（乱数の種は 0 に戻す） |
| `void openRecords()` | 記録の画面を開く（`--screen records`） |
| `void openStats(GameMode mode)` | 統計の画面を、`mode` のタブを選んで開く |

| メンバ変数 | 説明 |
|---|---|
| `config_` | 選んでいる設定 |
| `initialized_` | 設定ファイルの初期値（クールダウンの倍率・今のモードの視界）を読み込んだか |
| `showRecords_` / `showStats_` | 記録・統計の画面を開いているか |
| `stats_` | 統計の画面（絞り込みの条件を覚えておく） |

**視界の選び方**: 「通常 / 全視界」のラジオボタンです。モードを選び直すと、そのモードの初期値（`defaultFullVision`。settings.jsonc の `fullVision`）に戻します。モードごとに選んだ値は覚えません（推測で増やさない。初期値を変えたい時は settings.jsonc で変える）。

**`MenuAction`（構造体）**: `kind`（`None` / `Start` / `Quit` / `ChangeResolution`）と、`Start` の時の `config`、`ChangeResolution` の時の `resolution`。

**`DisplayState`（構造体）**: `App::displayState()` が毎フレーム作る、今のウィンドウの状態。`windowSize`（ウィンドウの時の大きさ。全画面の間は戻した時の大きさ）・`screenSize`（今描いている大きさ）・`frame`（タイトルバーと枠の分、全体が大きくなる量）・`workArea`（モニターの作業領域）・`fullscreen`。

**解像度の選び方**（根拠: 2026/11/03・11/14 の回答）: 「画面」の欄のコンボボックスで、`ui::resolutionList()` から選びます。画面に入らない解像度は「（画面に入りません）」と添えて灰色にし、選べません（`ui::fitsInArea`）。全画面の間は選べず、モニターの解像度で表示している旨を出します。今の大きさが一覧に無い時（settings.jsonc やコマンドラインで指定した大きさ）は「（一覧にない大きさ）」と添えます。選ぶ場所はメニューだけで、ポーズ画面にはありません。

**MainMenu.cpp の中だけ**:

| 名前 | 説明 |
|---|---|
| `ScalePreset`・`kCooldownPresets` | クールダウンの倍率の選択肢（実戦どおり ×1・2 分の 1・4 分の 1） |
| `nearlyEqual(a, b)` | 2 つの倍率がほぼ同じか（0.001 の誤差） |
| `drawCooldownScaleCombo(float& scale, float settingsScale)` | 倍率を選ぶ。設定ファイルの値が選択肢に無ければ、それも選択肢に加える |
| `drawTimeLimitSlider(MatchConfig&)` | 制限時間（1〜5 分） |
| `drawSkillDodgeOptions(MatchConfig&, const GameData&)` | 敵の数・敵の賢さ・制限時間と、登場する敵の一覧。賢さのスライダーの書式（`"%d（名前）"`）には、`ui::escapeFormat` を通した名前を入れる |
| `resolutionLabel(ui::WindowSize)` | 解像度の表示名（「1920 × 1080」） |
| `drawResolutionCombo(const DisplayState&)` | 解像度を選ぶ（上の「解像度の選び方」）。選び直されたら、その解像度を返す |
| `drawSkillShotOptions(MatchConfig&, const GameData&)` | 的の賢さ（敵の賢さと同じく、名前は `ui::escapeFormat` を通す）・大きさ・移動速度・制限時間。選んでいる値が選択肢に無ければ、大きさは真ん中の選択肢、速さは最初の選択肢にする |

**注意事項**:

- 選んでいるキャラ・ステージが見つからなければ（設定ファイルを消したなど）、一覧の最初に直します。
- 設定ファイルのエラーがあれば、メニューの下に赤字で出します。

### 2.2 記録（RecordsPanel.h / .cpp）

**背景**（根拠: `89cebb4`、指示書「直近 10 件のプレイは、それらのリザルトをユーザがスコアアタックの表示形式のように閲覧できる」）。

| 関数 | 説明 |
|---|---|
| `int rankOf(const vector<SavedResult>& recent, const string& playedAt)` | `recent` を順位の順（`rankedHigher`）に並べた時の、`playedAt` の結果の順位（1 始まり）。無ければ 0 |
| `void drawRecordTable(GameMode, const vector<SavedResult>& recent, const string* highlightPlayedAt, float maxHeight = 0)` | 順位表。割合の高い順に並べ、1〜3 位は金・銀・銅の色、`highlightPlayedAt` の行は青く強調する。列は 順位・成績・内訳・キャラ・ステージ・難易度・CD・視界・日時。表が `maxHeight` より高くなる時は、見出しを固定してスクロールする |
| `bool drawRecordsWindow(const ResultStore&)` | 記録の画面（メニューから開く）。モードごとのタブに直近 10 回の順位表を出し、最も新しいプレイを強調する。保存している件数と、保存のエラーも出す。「閉じる」で `true` |

順位の色・割合・難易度・クールダウン（`CooldownLabelStyle::Short`）・日時の表示は、共通の部品（[5 章の RecordFormat](#5-記録の表示の共通の書き方recordformath--cpp)）を使います。

### 2.6 デバッグパネル（DebugPanel.h / .cpp）

### 2.7 統計の画面（StatsDashboard.h / .cpp）

**背景**（根拠: `0498fab`、指示書「統計」）: 「自分の成長が分かりやすいように、ダッシュボードが表示され、各モードごとのグラフや特に優れたスコアに対するハイライト表示がある」という要件から作りました。配色は、色覚の多様性を考えて見分けやすい 3 色（青・橙・緑青）を使い、色だけで区別しないよう凡例・記号（◆・▲▼）も付けています。

画面の構成（StatsDashboard.h の先頭）:

```text
┌─ 統計 ──────────────────────────────────────────────┐
│ [閉じる]  説明                                        │
│ [スキルドッジ] [スキルショット]  ← タブ                 │
│ 絞り込み: キャラ / ステージ / 賢さ / 敵の数 or 大きさ・速さ / 期間 │
│ ┌プレイ回数┐┌平均┐┌自己ベスト┐┌直近 7 日┐ ← 数字の欄     │
│ ┌ 成績の推移（64%）──────┐┌日ごとのプレイ回数┐          │
│ ┌賢さごと┐┌キーごと（ショットだけ）┐┌自己ベスト TOP 3┐    │
│ ▸ この条件の記録の一覧（折りたたみ）                     │
└────────────────────────────────────────────────────┘
```

#### StatsDashboard.cpp の中だけ

| `shortDate` | 「10/25」（日ごとのグラフの目盛り。このファイルだけで使う） |

| `resultTooltip(const SavedResult&, const char* heading)` | グラフにカーソルを乗せた時の説明 |
| `drawTrendPlot(results, mode, size)` | 成績の推移。横軸は何回目のプレイか（プレイが少なくても 10 回分の幅を取る）。プレイごとの点・直近 10 回の平均の線（10 回分の数を合計してから割る。`movingAverage`）・自己ベストを更新したプレイの◆。最新の自己ベストにだけ数字を添える。数字は、枠からはみ出さないように、横軸の左端 2 割にある時は点の右、右端 2 割にある時は点の左、それ以外は点の真上に出す（上端に近ければ点の下）。総数 0 のプレイは描かない |
| `template drawBarPlot(title, labels, values, yMax, yFormat, yTickStep, size, tooltip)` | 1 色の棒グラフ（日ごとのプレイ回数・賢さごと・キーごと）。横軸の目盛りの名前は最大 10 個に間引く。`yTickStep` が 0 より大きければ、縦軸の目盛りをその間隔で決める。日ごとのプレイ回数では、目盛りを整数だけにする（8 個ほどになるように間引く）。割合のグラフは 0（ImPlot に任せる） |
| `drawTopResults(top, mode, size)` | 自己ベスト TOP 3（順位の色は `ui::rankColor`） |
| `drawResultTable(results, mode)` | 絞り込んだ結果の表（新しい順）。自己ベストを更新したプレイに印 |

**背景**（根拠: `91ad8b0` の修正、2026-10-31）: 以前は、自己ベストの数字を左に出すかを「プレイの数」で判断していたため、プレイが少ない時に左端の点の数字が枠の外へはみ出していました。また、プレイ回数のグラフの縦軸を ImPlot に任せていたため、上限が小さい時に「2, 2, 2, 1, 1…」と同じ数字の目盛りが並んでいました。

**注意事項**: 計算（`ResultStats`）は毎フレーム行います。保存している結果は最大でも 2 モード × 20 件 × 180 日 = 7200 件なので、毎フレームの計算でも問題にならない量です（推測）。

## 4. 文字の倍率（UiScale.h / .cpp）

**背景**（根拠: `9d287c1`、[dpi-scaling.md](../dpi-scaling.md)）: 拡大率 150% の PC で、ゲームの表示がほかのアプリの約 3 分の 2 の大きさになっていました。GLFW（raylib の中で使っている）が Windows に「DPI 対応」と伝えるため Windows は拡大せず、ゲームも拡大していなかったのが原因です。そこで、ピクセル単位の大きさに自分で倍率を掛けるようにしました。

2026-11-14 に、解像度を実際のピクセル数で選べるようにした時、**倍率の決め方を「Windows の拡大率 × `uiScale`」から「ウィンドウの高さ ÷ 900 × `uiScale`」に変えました**（ユーザーの選択）。拡大率で決めたままだと、拡大率 150% の PC で 1600×900 を選んだ時に、メニューが画面に入らなかったためです（[dpi-scaling.md](../dpi-scaling.md) の 6 章）。

### 4.1 関数

| 関数 | 説明 |
|---|---|
| `constexpr float ui::kBaseWindowHeight` | 倍率が 1.0 になるウィンドウの高さ（900）。`px()` に渡す大きさは、この高さの時の大きさで書く |
| `float ui::scale()` | 今の倍率（ウィンドウの高さ ÷ 900 × 設定の `uiScale`） |
| `float ui::px(float size)` | ピクセル単位の大きさに倍率を掛ける（ウィンドウの高さが 900 の時の大きさを渡す） |
| `ImVec2 ui::px(float x, float y)` | 幅・高さに倍率を掛ける |
| `void ui::setScale(float scale)` | 倍率を変え、Dear ImGui の文字と余白にも反映する。**最初に呼んだ時の見た目を倍率 1.0 の基準として覚え**、毎回そこから作り直す（倍率を掛けた結果にさらに掛けないように） |
| `float ui::scaleForWindowHeight(int windowHeight, float uiScale)` | ウィンドウの高さに合わせた倍率（高さ ÷ 900 × `uiScale`）。高さが 0 以下なら `uiScale` のまま。`App::applyUiScale` が使う |

### 4.2 使い方の決まり（UiScale.h の注意より）

| 場面 | `px()` を |
|---|---|
| `ImGui::PushFont(nullptr, size)` の `size` | **掛けない**（Dear ImGui が自動で倍率を掛ける） |
| `ImDrawList::AddText(font, size, ...)` の `size` | 掛ける |
| 座標・幅・余白などのピクセル値（`SetNextWindowSize`・`Button` の大きさなど） | 掛ける |
| ゲームの世界（キャラ・弾など） | 掛けない（カメラがウィンドウの大きさに合わせて拡大する） |

### 4.3 内部の状態（.cpp の中だけ）

`g_scale`（今の倍率）と `g_baseStyle`（倍率 1.0 の時の Dear ImGui の見た目）。どちらもファイルの中のグローバル変数です。

### 4.4 解像度の一覧と、画面に入るかの判定（WindowResolution.h / .cpp）

**背景**（根拠: 2026/11/03・11/14 の回答）: 解像度は、ウィンドウの時だけメニューの一覧から選びます（実際のピクセル数。Windows の拡大率は掛けない）。画面に入らない解像度は選べません。ウィンドウの縁をドラッグして大きさを変えることはできません（LoL・ER と同じ）。計算はテストできるよう、画面の部品から切り出しています（[tests/test_ui_scale.cpp](../../tests/test_ui_scale.cpp)）。

| 関数・型 | 説明 |
|---|---|
| `WindowSize`（構造体） | ウィンドウの中の大きさ（`width`・`height`。実際のピクセル数。タイトルバーと枠は含まない）。`==` で比べられる |
| `const vector<WindowSize>& resolutionList()` | 選べる解像度。16:9 と 16:10 の代表的なものと、2160×1440（3:2）・2400×1350（16:9）（根拠: 2026/11/14 のユーザーの指定）（1280×720・1280×800・1440×900・1600×900・1680×1050・1920×1080・1920×1200・2160×1440・2400×1350・2560×1440・2560×1600・3840×2160）。ピクセル数の少ない順 |
| `bool fitsInArea(WindowSize size, WindowSize frame, WindowSize area)` | 中の大きさ `size` に、タイトルバーと枠の分 `frame` を足したウィンドウが、作業領域 `area` に入るか。作業領域が分からなければ（0）入るとみなす |
| `WindowSize startupWindowSize(WindowSize wanted, WindowSize frame, WindowSize area)` | 起動時の大きさ。`wanted`（settings.jsonc の `window`）が入ればそのまま。入らなければ、一覧の中で入る最も大きいもの（**同じ縦横比のものを優先**。Claude判断: 16:9 を選んでいた人が、16:10 に変わらないように）。どれも入らなければ一覧の最も小さいもの |

## 5. 記録の表示の共通の書き方（RecordFormat.h / .cpp）

**役割**: 記録（プレイの結果）を表示する時の書き方を 1 か所にまとめます。記録の表（`RecordsPanel`）・リザルト画面（`ResultScreen`）・統計の画面（`StatsDashboard`）で、同じ内容が同じ形で出るようにするためです。名前空間は `moba::ui` です。

**背景**（根拠: `0220ef3` の修正、2026-10-30）: 以前は同じ関数・定数が画面のファイルごとにあり、片方だけ変えると表示がずれるおそれがありました。決まり（ユーザーの指示）は次のとおりです。

- まったく同じ役割・処理のものは、共通の場所にまとめる
- 違う所があるものは、共通の部分だけを抜き出し、違う部分をそれぞれの呼び出し元から渡す

| 関数 | 説明 | 使う画面 |
|---|---|---|
| `string difficultyLabel(const MatchResult&)` | 難易度（スキルドッジ:「敵 3 体・ふつう」、スキルショット:「ふつう・標準・340」） | 記録の表・統計 |
| `string shortTime(const string& playedAt)` | 保存した日時の短い表示（「2026-10-25 22:40:12」→「10-25 22:40」。形が違えばそのまま） | 記録の表・統計 |
| `string percentText(const ResultScore&)` | 割合（「52.0%」。総数 0 なら「-」） | 記録の表・リザルト画面・統計 |
| `ImVec4 rankColor(int rank)` | 順位の色（1〜3 位は金・銀・銅、それ以外は白） | 記録の表・統計の TOP 3 |
| `string cooldownLabel(const MatchConfig&, CooldownLabelStyle)` | クールダウンの設定。「なし」か倍率かの判断は共通で、標準の時の書き方を引数で選ぶ | 記録の表（`Short`）・リザルト画面（`WithMode`） |
| `string visionLabel(const MatchConfig&)` | 視界の設定（「通常」/「全視界」） | 記録の表・リザルト画面 |

`CooldownLabelStyle`（列挙型）:

| 値 | 標準の時の表示 | 使う所 |
|---|---|---|
| `Short` | 「×0.25」 | 記録の表など、狭い所 |
| `WithMode` | 「標準（×0.25）」 | リザルト画面 |

どちらも、クールダウン「なし」の時は「なし」です。

**注意事項**: HUD のドッジ率（「52.0%（13 / 25）」）や、リザルト画面のキーごとのヒット率（小数なしの「52%」）は書き方が違うので、この部品を使っていません。

## 6. スキルバーの大きさ（HudLayout.h）

**役割**: 画面下中央のスキルバーの大きさの定数です。`render/Hud.cpp` がスキルバーを描き、`ui/SandboxPanel.cpp` が練習場のパネルをその上にそろえます。どれもウィンドウの高さが 900 の時のピクセルなので、使う時に `ui::px()` を掛けます。

| 定数 | 値 | 説明 |
|---|---|---|
| `ui::kSkillBarBoxSize` | 58 | キー 1 つ分の四角の大きさ |
| `ui::kSkillBarBottomMargin` | 44 | 四角の下端から画面の下端まで（スキル名を出す分） |
| `ui::kSkillBarHeight` | 102 | 画面の下端からスキルバーの上端までの高さ（上の 2 つの和） |

**背景**（根拠: `0220ef3` の修正、2026-10-30）: 以前は練習場のパネルが `58 + 44` を自分で持っていて、スキルバーの大きさを変えるとパネルと重なるおそれがありました。

`render/Hud.h` ではなく `ui/` に置いたのは、`ui` → `render` という今まで無い向きの依存を作らないためです（`render` → `ui` の向きは、`UiScale.h` ですでにあります）。

## 7. 書式に入れる文字列（ImGuiText.h）

| 関数 | 説明 |
|---|---|
| `std::string ui::escapeFormat(std::string_view text)` | `%` を `%%` にした文字列を返す。設定ファイルの文字列（賢さの名前など）を、`SliderInt` の `format` のような printf 形式の書式に入れる時に使う |

**背景**（根拠: claude_improve_and_answer.txt の「B4について 表示側で直す形を採用する」、2026/10/31）: 書式の中の `%` は値の指定として読まれるため、名前に `%` があると、関係の無い値を読みに行きます。名前を確かめて `%` を禁止するのではなく、表示する側で `%` をそのまま出すようにしています。

**注意事項**: 文字列を `"%s"` の引数として渡す時（`ImGui::Text("%s", name)` など）や、`TextUnformatted` を使う時は要りません。書式そのものに文字列を埋め込む時だけ使います。
